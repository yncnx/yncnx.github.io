使用GitHub Actions自动部署Hexo

因是2023-08-052026-08-16

前言

  之前每次部署 Hexo 都需要运行 hexo cl & hexo g & hexo d 指令三件套完成推送到远程仓库，换一台电脑还要重新部署环境，而且随着文章越来越多，编译的时间也会越来越长。现在通过 GitHub Actions，我们只需要在每次完成博客的编写或修改以后，将改动直接 push 到远程仓库，之后的编译部署的工作统统交给 CI 来完成即可。

  本文假设你已经有了自己的 hexo 静态博客，因此只介绍自动化部署的过程合设置。通过 CI 持续集成，可以省去本地环境的重复搭建，每次只需推送源码即可触发自动构建与发布，大幅提升博客维护效率。

一.创建GitHub仓库

  首先需要在 GitHub 上创建两个仓库：一个用于存放 Hexo 源码，另一个用于存放编译后生成的静态页面。

  1. 创建 blog 仓库用来存放 Hexo 源码，仓库的类型是 private
  2. 创建 yourname.github.io 仓库用来存放静态博客页面，仓库类型是 public（yourname修改为自己GitHub用户名）

二.部署密钥

  部署密钥用于让 GitHub Actions 在编译完成后有权限将静态文件推送到 yourname.github.io 仓库。

五.查看部署

  若部署失败，可在 Actions 页面查看运行日志定位问题。常见原因包括密钥配置错误、Node.js 版本不兼容或依赖安装失败等，根据日志提示逐一排查修复即可。
